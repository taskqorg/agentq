# AgentQ — the shared worker layer

Revision: 6. Product outcomes; decisions and the requirement map live in [agentq.md](../../agentq.md) §11. [Acceptance](VERIFICATION.md). Shared ownership: [specq agent runtimes](https://github.com/taskqorg/specq/blob/main/engineering/agent-runtimes.md).

## Purpose

AgentQ is the single worker layer for native agents: prepare, launch, resume, observe, control, history and archive. Products use one runtime contract and keep their own task admission, grants, scheduling and UI. Native differences belong in AgentQ's per-runtime registry modules.

The runtime library and JSON turn command work without a service installation. Optional host installation adds native record hooks, local telemetry, enrollment, transactional updates and ownership-based integration controls. Codex, Claude Code and Antigravity are worker runtimes; Hermes has a record integration. Claude Desktop Chat has no current integration.

This is the product scope, not a claim that every accepted target is shipped. [RUNTIME](RUNTIME.md) names implemented operations, including worker preflight, and remaining archive targets; the shared contract owns history and archive under their grants. Unsupported or unverified operations stay explicit. DashQ owns fleet presentation; CoreQ owns shared process, storage, release and service primitives.

## Requirements

- **R1 — One managed package.** Support macOS, native Windows and Linux; WSL has its own runtime on the same host. Manage Codex CLI/Desktop, Claude Code CLI/Desktop Code and qualified Hermes record integrations. One local management entry point owns needed child processes; no manual per-agent service administration. Claude Desktop Chat setup is unsupported.
- **R2 — Retired document tools.** `index_document`, `search_document` and `get_original` are retired. Their decision and measured use have one home in [OPTIMIZATION-RETIRED](OPTIMIZATION-RETIRED.md).
- **R3 — Retired optimization.** Context optimization is retired. Native commands, results and context stay native; [the retirement decision](OPTIMIZATION-RETIRED.md) owns the measurements and sole return condition.
- **R4 — Preserve work.** Keep requests, native authentication, model, approvals, sandbox, hook trust and conversation history unchanged. Preserve the exact direct Codex provider definition for saved conversations. Retained data is not removed by qualification.
- **R5 — Easy onboarding.** One link starts agent-led discovery; offer all ready clients, allow deselection and reuse known TaskQ profiles. Request only missing input and required consent. Resolve actual roots and user/project/environment precedence, show shared aliases and Desktop reload requirements, keep unrelated settings and verify real activity from each selected profile. Configured is not verified. Team login uses device enrollment; employees receive no shared Langfuse secrets.
- **R6 — Transactional updates.** CoreQ owns release checksums, launcher, rollback and OS service updates. Upgrade cleanup retires only unchanged journal-owned legacy integrations, preserves foreign edits and reports conflicts.
- **R7 — Ownership and removal.** Record each created/reused component and config edit before mutation, including owned native telemetry plugins. Dry-run previews removal; uninstall restores unchanged owned settings and removes owned dependencies, plugins, services and data. Preserve pre-existing/shared components, login, later edits and exported history; report conflicts. Repeat install/remove is safe. Disable and enable work with the service stopped and restore only supported saved fields.
- **R8 — Small, reliable state.** Durable local state holds ownership, identities, transactions, versions, incidents, retained original references and telemetry. Use the simplest adequate storage, with no separate local database server; SQLite is a technical choice, not a product requirement. Preserve existing retention, freshness, recovery policy and operating limits; add no new timeout, cap, budget, cache, retry limit or queue bound, unless a real failure needs it. Serialize lifecycle changes and recover interrupted transactions. Secrets stay protected, outside telemetry.
- **R9 — Consistent telemetry.** Native record hooks and runtime observations persist local call and turn metadata, with optional Langfuse export and enrollment. Unknown stays unknown; secrets and content stay outside default metadata. History and archive are separately authorized content, not telemetry.
- **R10 — Honest accounting.** Attribute observed input, cache and output usage, latency, errors and reported cost once. Keep usage categories, source time and missing-value reasons. DashQ owns fleet presentation; retired optimization fields are unavailable, never zero savings.
- **R11 — Simple development and release.** One codebase, repeatable builds and checks, and small unavoidable OS adapters. Reuse ready components, platform facilities and prebuilt artifacts; users do not assemble toolchains. Added code, dependency, service or step needs a real benefit. Preserve effective behavior and reliability; add no speculative framework. New runtime starts from an empty codebase, not inherited legacy implementation.
- **R12 — Spec-driven changes.** An AI manager assigns bounded work against an approved spec revision; products retain task admission. Independent acceptance verifies integrated outcomes before authorized merge/deploy. Behavior changes require discussion/evidence, an approved spec amendment, then implementation. Use meaningful product scenarios and targeted risk checks, without test-count or coverage quotas or function-by-function duplication.
- **R13 — Reusable worker layer.** Products reach agent preparation, launch/resume, cancel, observation, control, step history and archive through AgentQ. Preserve native modes, accounts, tools, abstract policy, recovery and attributable observations. A plain turn needs no service installation. Caller admission and grants stay caller-owned; archive content needs its grant. Optimization intent remains a compatible no-op until pinned TaskQ, PilotQ and Pipe consumers adopt its retirement.
- **R14 — Reliable worker start.** Before a worker receives its task, the runtime checks everything that worker needs and repairs only what it owns. Start ready or refuse before spending tokens, with the exact cause and next step. A worker never silently waits for a person. Optional observation failures never stop work. Unverified readiness stays visible, never reported as ready. [Worker preflight](RUNTIME.md#worker-preflight) implements the checks and owned repairs; native qualification remains separate.

R1–R14 retain their outcome identities. R2 and R3 are explicitly retired; R4/R6/R9/R10/R13 carry their compatible replacement behavior. Historical optimization accounting definitions remain [archived](ACCOUNTING.md); current model-call and turn semantics live in [TELEMETRY](TELEMETRY.md) and [RUNTIME](RUNTIME.md).

Technology, support gaps and qualification live in [agentq.md](../../agentq.md), [RUNTIME](RUNTIME.md) and [VERIFICATION](VERIFICATION.md). Qualification does not authorize deploying a candidate to working profiles.
