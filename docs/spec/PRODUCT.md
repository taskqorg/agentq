# AgentQ — internal organization package

Revision: 3. Product outcomes; decisions and the requirement map live in [agentq.md](../../agentq.md) § 11. [Acceptance](VERIFICATION.md).

## Purpose

Install once per machine/runtime. Manage our agents' optimization, updates and telemetry centrally. Replace optimization tools later without rebuilding onboarding, fleet control or observability. Users do not maintain a service per client. Upstream tools do the optimization; our small package manages their integration.

AgentQ also owns the reusable Codex/Claude worker runtime that TaskQ, PilotQ and other products use to run agent turns. A plain agent turn needs no optimizer installation; optimization is an explicit, optional choice per launch (R13).

## Requirements

- **R1 — One managed package.** Support macOS, native Windows and Linux; WSL has its own runtime on the same host. Manage Codex CLI/Desktop, Claude Code CLI/Desktop Code and qualified Hermes integrations. One local management entry point owns needed child processes; no manual per-agent service administration. Claude Desktop Chat supports explicit MCP only.
- **R2 — Replaceable tools.** Stable package-owned MCP exposes index_document, search_document, get_original; CLI runs native commands in the client sandbox. Internal adapters call versioned engines. Engine replacement preserves client registrations, tool names and instructions. The owner-approved 0.9.0 namespace cutover uses `agentq`; existing chats bound to the retired provider are explicitly not migrated (agentq.md § 4). Proxy routes traffic/telemetry; it never injects tools. Initially RTK handles qualified noisy commands; context-mode handles selective reference retrieval. Tool replacement preserves enrollment, identities, update control and telemetry history. Use small adapters to upstream CLI/MCP/HTTP interfaces; do not force every tool into one string-compressor API. Report unsupported capabilities and version combinations.
- **R3 — Effective optimization.** Optimize only qualified workloads. Code, complete JSON, dense constraints and short results pass through by default. Native RTK execution preserves requested command semantics; generic postfiltering is not equivalent. Keep native compaction; transform a new result once and reuse it unchanged. Choose recipes by paired whole-task quality/usage, not isolated reduction. No required cloud key/model download or universal savings promise.
- **R4 — Preserve work.** Keep user requests, auth, model, approvals, hook trust, IDs/order, exit/error evidence, nontext and signed/encrypted reasoning. Never rewrite transmitted prefixes. Retain original recovery without recompression/re-execution; report expiry. Optimization failure or full storage keeps the original. Proxy failure has bounded recovery and an independent, safe restore-direct-access command; no silent provider switch.
- **R5 — Easy onboarding.** One link starts agent-led discovery; offer all ready clients, allow deselection, reuse known TaskQ profiles. Request only missing input/required consent. Resolve actual config roots and user/project/environment precedence, including Desktop reload requirements. Explain changes, keep unrelated settings, verify real activity from each selected profile; configured is not verified. Team login uses device enrollment; employees receive no shared Langfuse secrets.
- **R6 — Updates and replacement.** Verify qualified release signatures/checksums and compatibility; notification triggers an early check, hourly check is fallback. OS service owns permanent TCP ingress and supervisor. Stage a ready versioned worker on a separate port; atomically route new connections, retain existing connections on old worker. Max two workers; serialize updates. Retire after 15 min, allow 30 s graceful exit, then kill owned process tree with visible incident. Installation-owned durable queue has one sender. Verify actual active/retiring versions; failed update rolls back. Show pending/migration states. Engine and client updates recheck compatibility. Migration explicitly disables obsolete owned routes/hooks/processes; no parallel double compression or accidental revival of experimental integrations.
- **R7 — Ownership and removal.** Record each created/reused component and config edit before mutation, including native telemetry plugins. `uninstall --dry-run` previews; `uninstall` restores owned settings and removes owned dependencies, plugins, services and data. Preserve pre-existing/shared components, login and later unrelated edits; report conflicts. Repeat install/remove is safe. Disable/restore works even if proxy is down. Existing exported history remains.
- **R8 — Small, reliable state.** Durable local state holds ownership, identities, transactions, versions, incidents, original references and telemetry queue. Choose the simplest adequate storage in the technical plan; SQLite is an option, not a product requirement. No separate local DB server. Set explicit timeouts, memory/disk/queue caps, retention/freshness and recovery policy before qualification. Serialize lifecycle changes; survive interrupted transactions. Secrets stay in protected storage, never telemetry.
- **R9 — Consistent telemetry.** Export to shared Langfuse `Agents` through a bounded durable queue; outage cannot block agent work. Events have schema/version, stable ID, timestamp/stage and relevant owner, account, host/runtime/installation/profile, agent/service, actual package/recipe/engine/config versions. Preserve native session/turn/request/attempt/tool correlation; unknown data has a reason. Stable IDs—not names/IP—drive joins; aliases avoid duplicate users. Retain native telemetry hooks only with normal trust; no Codex compression hooks in the initial recipe. Default new events contain metadata, not raw content; preserve existing approved capture choices.
- **R10 — Honest accounting and dashboard.** Measure model input/cache/output, attempts, retrieval/rework, latency, errors and cost source/currency once. Distinguish observed usage, estimates, fees and unknown values; gross reduction is not task or subscription savings. Primary dashboard shows every enrolled installation, actual/target version, last seen and component health, then each agent's activity, recipe, coverage, usage, optimization outcomes and incidents. Stale/unknown/uninstalled states remain explicit. Agent-readable queries use the same data/definitions and trace references. Include TaskQ/ServerQ health through their existing interfaces. Admins see organization data; members see their own; device access can be revoked.
- **R11 — Simple development/deploy.** One codebase and repeatable build/test/release workflow; small unavoidable OS adapters. Prefer ready upstream components, platform facilities and prebuilt artifacts; users do not compile or assemble toolchains. Added code/dependency/service/step requires a real benefit. Preserve effective features and reliability; no speculative framework. New runtime starts from an empty codebase, not inherited legacy implementation.
- **R12 — Spec-driven agents.** AI manager assigns bounded tasks against an approved spec revision. Independent acceptance verifies integrated outcomes before authorized merge/deploy. Behavior changes require discussion/evidence, approved spec amendment, then implementation. Minimum meaningful product scenarios plus targeted high-risk checks; no test-count/coverage quota or function-by-function duplication.
- **R13 — Reusable agent runtime.** Products run Codex and Claude worker turns through one AgentQ runtime library and a thin JSON command for non-Rust callers, without installing the optimizer service, Headroom, RTK or MCP. Preserve CLI, background, app and app-server modes, Remote Control, session recovery, native tools, private drafts, the model catalogue, accounts, permissions and exactly one attributable usage observation per turn. Each launch states optimization intent `inherit`, `off` or `on` and sees the effective state with a reason; host disable wins, a launch never edits global configuration, and an absent or failed optimizer keeps native output. CoreQ keeps generic primitives; its frozen agent module stays compatible until every consumer adopts the runtime.

## Evidence and limits

Our experiments support noisy-command reduction and selective retrieval. They do **not** prove a released combined recipe or universal net savings. Tokenade saved input on noisy Claude tests but caused extra JSON reading; its live Codex probe did not compress. The experiment reports stay in git history before taskqorg/agentq#62.

Technology, operating limits and rollout policy live in [agentq.md](../../agentq.md). New code must meet this contract; old product deletion/deployment is a separate authorized step.
