# AgentQ connection

Accepted target under [agentq.md](../../agentq.md), PRODUCT R5/R9/R10. [Shared semantics](https://github.com/taskqorg/specq/blob/main/engineering/product-connections.md); [complete scenario, limits and E1–E10](https://github.com/taskqorg/dashq/blob/main/docs/design/enrollment.md). Not a shipped-command claim.

- `agentq enroll <https-url>` reuses installation/service/update state and the coreq connection client. Browser or headless approval uses DashQ's identity provider; no GitHub token, copied key, onboarding rerun, capture or routing change.
- `agentq connection status` reports destination, connection/projection/export state and safe recovery action. `agentq disconnect` follows C1, including pending offline revocation. JSON matches CLI facts; no secrets.
- Existing `data/installation` remains identity. Snapshot allowlists version, runtime, component/routing/engine state, queue counters, source timestamps and resource samples with unknown reasons. Raw status, paths, prompts and arbitrary OTLP attributes never cross enrollment.
- Snapshot schema 1 (`agentq/snapshot.rs`, a pure projection of `status.json` and the newest `agentq.resource` span): `schema`, `installation`, `runtime`, `version`, `status_at`; `service` `running` or `unknown` with `no status`, `status without time` or `stale status` (over 90 s); `update` `available` and an `error` flag; `routing` per known agent as its enum only; `engines` rtk/headroom pin and `ready`, `unavailable` or `unknown`; `queue` `pending`, `oldest_age`, `last_delivery`, `dropped` and a `send_error` flag; `resource` `event_id`, source `at_ns`, the § 6 numbers and disks (`id`, `role`, `fstype`, bytes). Missing values are null or `missing`, never zero; `<probe>_unknown` keeps `warmup`, `counter reset`, `wsl1 mirrors the Windows host`, `no sampler on this OS`, `no local filesystem`, else `probe failed`; no sample yet gives `resource.unknown`. Host name, pid, reason and error text never cross. Additive `configuration` (CONFIGURATION A2): `older producer`, `no status` or `unsupported schema` stay unknown; profiles carry kind-derived label/aliases/operations, fixed enums and codes, verification `unknown`, a capped project `overrides` count (null when unknown) and writes disabled with reasons (`not_released`, `stale`, `truncated`, `incomplete`, `conflict`, `project_override`).
- Use the existing sender queue and C5 cadence/bounds. Wake immediately for first real snapshot; keep the existing resource probes and 300-second history cadence. Enrollment completion is independent of CPU warmup, chart history and Langfuse export.
- Preserve standalone configuration until new projection receipt verifies it. New records switch atomically; old records retain destination/generation and consent. Disconnect does not revive the old destination. Accepted receipt precedes queue deletion; retransmissions retain IDs.
- Protected per-installation credentials and revoke state are excluded from queue pruning and update cleanup. Never migrate a credential into another installation or runtime.
- C3's owner-accepted credential lifetime exception is observation-only. No task actions, remote execution or shared employee secrets.
- Release requires installed desktop/headless and storage/service qualification on macOS, Linux, native Windows and WSL, plus E1–E10 applicable to AgentQ. Existing resource qualification is reused; no fake workload or invented chart samples.
- Implementation (`agentq/connect.rs`, coreq v0.7.0 `enroll`): state in protected `data/connection/` seeded with `data/installation`; grant scope `agentq-snapshot/1`; the destination stays the DashQ origin and every coreq route is posted under `/machine/` (dashq#110), e.g. `/machine/connect/device`, `/machine/ingest`, `/machine/operations`; snapshot records are `<unix seconds>-<event id>.rec.json` in `data/queue/` under its caps, coalesced while unsent per grant and resource sample, delivered by the service sender every 60 s with coreq backoff. `enroll` delivers its own first snapshot and polls the receipt every 2 s for 60 s; `verified.json` records the projected event. A rejected record is deleted and counted in `dropped`; another grant's record is rejected unsent. Langfuse spans keep their standalone destination: the grant carries no event schema yet.

Accepted additive profile projection and separate configuration capability: [A1–A5](CONFIGURATION.md). Existing observation grants never gain mutation authority automatically.

Additive release metadata for DashQ D18 follows [the release observation contract](../../agentq.md#dashq-release-observation): snapshot `release` and heartbeat `agentq.release` share one allowlisted projection of the service observation. The existing installation identity and release `at` identify the source. Health verifies only the running release status-write receipt, never a client round trip or the selected candidate.

Persistent checks protect selection versus running identity, stale/future health, marker validity, unreadable control state, the CoreQ lockfile pin and status-to-OTLP wiring. Existing routing, profile and ownership checks remain intact; no acceptance rule is weakened.
