## Exact proposed trait surface

Reuse existing `Run`, `history::Step`, `Launch` and `Failure`; add no public request, reply, transport or configuration type:

```rust,ignore
fn fork(&self, source: &mut Run, through: Option<&history::Step>, launch: &Launch)
    -> Result<Run, Failure>;
fn rewind(&self, source: &mut Run, through: Option<&history::Step>)
    -> Result<(), Failure>;
```

The descriptor capabilities are `fork` and `rewind`, independently. Undeclared operations return `Failure::Refused(Cause("fork-unsupported"))` or `Failure::Refused(Cause("rewind-unsupported"))` before spawn, input or mutation. A static capability names an adapter path, not evidence that every native version, mode or history boundary supports it. Native unknown/missing support refuses explicitly; there is no flag fallback, local transcript surgery, second control protocol or compatibility path.

`through: Some(step)` retains conversation through that exact step, inclusive, only when it is the last retained native chain entry of a completed whole turn. A mid-turn/tool/thinking/partial or ambiguously associated step refuses; never silently round to a turn boundary. `None` means the empty conversation prefix, not latest or full history. An adapter unable to represent that boundary natively refuses it. A caller forking the current tip supplies its validated final step explicitly. The whole-turn boundary is a supported target definition, not a claim that every arbitrary history step is a native mutation cursor.

A `Step` is selection data, never authority. Re-resolve its stable ID, revision, session and source/origin byte ranges/hashes against the current owned source, then derive native cursors inside the registered adapter. Do not trust caller-supplied `native_id`, turn ID, array index or cached display order. Unknown, stale/replaced/truncated or foreign source, revision, boundary or native identity refuses before mutation. History keeps its existing read-only authority.

Both methods require the source's current mandatory SessionOwner, matching runtime/project/account/store binding, known idle native state, a writable transport, no pending or uncertain C285 request/input/steer/compaction and no unresolved stop or mutation. A terminal turn with a live owned transport can be idle; a missing transport, process exit, silence or recovered observation-only checkpoint does not create mutation authority. Do not reopen a recovered run or adopt it implicitly. Parent admission remains held across native selection and submission. Parent/child owners, lifetimes and process scopes remain distinct.

`fork` returns a new owned `Run`; its source session and files remain untouched by the fork operation. Normal `Launch` validation, preflight, explicit input, policy, model/effort/instructions, caller hooks and lifetime rules apply to the child. The first slice keeps canonical project root, account home and SessionStore equal to the source; an unsupported scope/condition change refuses rather than silently inheriting it. Filesystem comparison setup belongs to the caller; this API neither creates nor restores a worktree, and the first slice refuses a changed project root. Child continuation may subsequently edit the shared working files under its normal Policy; unchanged parent conversation does not mean unchanged workspace state. Requested and observed conditions remain separate; omitted model is not evidence of the parent's effective model. Native creation and child ownership/lineage binding precede explicit prompt submission; caller-selected child IDs use the existing caller-session-ID ownership path, not assumed native acceptance. Foreign or source-equal returned child IDs fail closed before child input.

`rewind` changes the current session's durable conversation prefix in place, submits no model input and changes no model, permissions or files. It succeeds only on matching native acknowledgement plus authoritative retained-prefix readback. Retaining the already-current tip is a read-verified no-op. Rewind does not manufacture a new Claude child under the old ID. Already frozen reports/accounting snapshots and accepted raw archive bytes remain immutable; subsequent history is a new source generation when the native source changes. Next input remains a separate existing operation.

A lost/partial write, malformed/foreign response or unverified prefix is `Failure::Failed` with outcome unknown, not a refused pre-write operation or success. Retain private native evidence and the original owner fence; never resend, auto-resume, roll back, delete an uncertain child or switch transports. A read-only inventory/history cannot clear a mutation fence by itself. Readback/reconciliation must prove the original operation and scope before allowing another mutation. No new public recovery protocol is proposed here.

Forks never copy C285 pending request capabilities, run IDs or generations. Old reply tokens and copied journal rows cannot answer a child request. Rewind retains C285 occurrence fencing; it does not reset generations or revive removed-turn requests. Private requests, answers, raw bytes and lineage stay session content, never telemetry. Protected/external scopes refuse unless their existing authority explicitly supports this operation; process/descendant settlement is not inferred from conversation mutation.

## Native mapping and capability boundary

| Runtime path | Fork | Rewind | File state |
|---|---|---|---|
| Codex owned app-server | `thread/fork` with source `threadId` and inclusive `lastTurnId`; validate distinct `result.thread.id` and effective configuration | Paginated thread only: `thread/revert {threadId, beforeTurnId}` removes that turn and later turns | Persisted conversation only; working files and external effects are not restored |
| Claude native print/headless | `--resume <parent> --fork-session --resume-session-at=<last retained chain UUID>` with normal explicit child model/input; source support is established, AgentQ implementation/qualification remains pending | No demonstrated in-place conversation-revert operation in inspected CLI/SDK contract; `rewind-unsupported` | Fork copies no file-history snapshots; files, worktree, undo history and external effects are not restored |
| Claude interactive/background, Desktop, Antigravity ACP/old seam, Grok, OpenCode/OpenCode2, OMP, Pi, Hermes, fake/custom undeclared runtimes | Explicit unsupported until a registered native boundary path has evidence and tests | Explicit unsupported | No restoration claim |

Codex source is official `openai/codex` tag `rust-v0.162.0`, commit `c1382380de69521303b416720a52f42d51af6248`: `app-server-protocol/schema/typescript/v2/Thread{Fork,Revert}{Params,Response}.ts`, `src/protocol/v2/thread.rs`, and native `app-server/tests/suite/v2/thread_{fork,revert}.rs` under `codex-rs/`. `lastTurnId` is inclusive and cannot identify an in-progress turn. The fork tests assert original rollout bytes unchanged and named-prefix retention. Revert response has empty `thread.turns`; hydrate authoritative history with returned cursors and `thread/turns/list`/`thread/items/list`, never treat an empty inline list as an empty conversation.

For inclusive rewind through turn A, locate the first following turn B and send `beforeTurnId=B`; empty prefix uses the first native turn, and a proven empty source/tip is a no-op. Refuse legacy history or absent/ambiguous turn mapping. Do not substitute `thread/rollback`. Empty-prefix fork uses native `beforeTurnId` only after experimental native support is verified; it is experimental and omitted from the stable generated TypeScript schema, although present in pinned Rust definitions/tests. Do not interpret absent `lastTurnId` as empty: it forks full history.

Pinned Rust also exposes experimental `deferGoalContinuation`: a fork may inherit a native goal that otherwise starts automatic continuation. Suppress that native continuation before explicit input using verified native support, or refuse a goal-bearing/unverifiable path before fork. No additional model turn may start before child ownership and explicit caller input. Native method/field refusal stays unsupported/unknown; no optional runtime config, local fallback or new retry is added.

Claude source evidence: official CLI reference documents `--fork-session` as a new ID on resume. SDK `@anthropic-ai/claude-agent-sdk@0.3.284` documents inclusive `forkSession(upToMessageId)`, fresh UUIDs, preserved parent chain and absent file-history snapshots. Its `resumeSessionAt` maps directly to `--resume-session-at=...`; `forkSession` maps to `--fork-session`. The SDK warns that interactive/background boots ignore truncation/guard options: only print/headless is admissible. A retained turn can end with a tool-result carrier and `structured_output` attachment; choose its last actual chain entry, never merely the last assistant UUID. Unknown tail mapping, missing flags, compaction/UUID remapping or lack of safe child admission refuses before input. Empty-prefix native Claude fork is not established by this evidence and initially refuses; a fresh launch must not be mislabelled a native fork.

Do not add Node/SDK execution or reimplement its transcript copy/remapping in Rust. Orca's `claude-rewind-transcript.ts` is evidence of SDK behavior, not a transport AgentQ may silently depend on. SDK source support is not installed-version or native different-model proof. `rewindFiles()` is a separate checkpointing operation, not conversation rewind, and is outside this contract. No working profile or native binary is invoked for preparation.

## Shared history/archive linkage proposal

The original table at immutable blob `20f490ead4055c94490741a976659e17ba511864` is retained as historical proposal, not a compatible wire contract. Current `Source.parent_step` is a native call/item ID, and local `Step.id`/revision/origin domains do not equal sink reconstruction. Do not overwrite these fields or add the previously proposed keys to the exactly-15-key archive manifest.

[SESSION-LINEAGE-WIRE.md](SESSION-LINEAGE-WIRE.md), token **F300-L20261107-2**, is the single revised portable lineage/condition proposal. It reuses the existing archive range envelope for a read-only sidecar, separates private native evidence from scrubbed archive anchors, and requires centrally reviewed producer/reader integration. ## Local runtime preparation boundary (2026-11-07)

The exact runtime API ACK remains F300-20261107-1; local source preparation uses unaccepted coherent #285 `64330c7f0fe843d6d0d6673124ef6e33a548d53a` only as a development dependency. This does not accept #285 or the L2 wire proposal. Publication/acceptance waits for accepted coherent #285, exact independent source review and authorized qualification.

The first local implementation targets owned Codex app-server control runs, with the existing client probe reporting the source-inspected protocol version `0.162.0`. Missing/different native version evidence refuses; this is an evidence boundary, not native qualification. Read-only `thread/goal/get` must explicitly return a null goal; missing support, malformed result or any goal refuses, rather than assuming auto-continuation suppression. Empty-prefix fork refuses because this connection has no verified advertisement for experimental `beforeTurnId`; empty-prefix rewind remains representable through the first native turn. New MCP/instructions/effort overrides refuse in this first slice because their effective fork condition readback has not been established; ordinary launch behavior is unchanged. Explicit model and the existing mapped policy remain available. Other runtime/mode paths retain explicit refusals.

The selected journal must still match the held file identity and append position; replacement, truncation, foreign append and child log aliases refuse. Only exact `codex-app-server` native `item/completed` assistant message Steps from the owned private journal are eligible. Re-read the entire current journal through the existing public `History` reader and compare the full Step (including stable ID, revision, physical source and all origins), then match its native item to the last item of an authoritative full completed turn. Every later native turn must have a known root chain and must not continue the selected root chain. Unknown root chain, partial items, paginated cursor anomalies, malformed/foreign records, incomplete tails and arbitrary rollout/snapshot selections refuse. This deliberately does not equate item completion with whole-turn completion. Existing native turns are paged in source order using `itemsView: full`; empty revert response arrays are never retained-prefix proof. Read the resulting turns independently and compare the complete retained prefix.

The owner journal durably records a private mutation intent and selected-boundary evidence before native mutation. All input/control/adoption/re-admission stays fenced until matching authoritative readback and durable completion. A lost response remains unknown and is never replayed, including after process exit or observation-only recovery. Parent and child lineage persists in the local ownership journal independently of optional archive delivery; no L2 field, archive payload, public lineage type or content identity is consumed. Child fresh admission, native identity binding, effective requested model/policy/root readback and private lineage precede exactly one explicit input through the ordinary launch path; hooks, lifetime scopes and existing reporting/accounting remain in that path. Prior frozen reports remain unchanged.

For broader history selection, the minimal proposed history-owner hook is an adapter-private read-only resolver taking the owned physical source binding plus an exact Step, returning its revalidated physical records, native turn/item association and source generation witness, or a named refusal. It must not mint mutation authority or infer a terminal chain boundary. Codex native readback must still prove whole-turn/last-chain selection. No hook or history-owned source is changed in this preparation.

The child obtains fresh alias admission and its own native transport before `thread/fork`; the parent transport performs only selection/readback. The returned child ID is bound and its prefix/effective conditions are checked before the single explicit prompt on that same child transport. Do not fork on the parent server and then open another server on the returned child: official `thread_unsubscribe.rs` at `c1382380` demonstrates that unsubscribe retains the loaded thread until an idle unload, so it is not an immediate ownership transfer. No unload delay, polling or retry is introduced. Native creation replies remain private durable mutation evidence even if later child startup/readback fails.
