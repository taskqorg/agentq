# Session archive

Binding detail of [agentq.md M6.12–M6.13](../../agentq.md#session-archive). The archive follows the [specq archive rule](https://github.com/taskqorg/specq/blob/main/engineering/profiling.md#agent-session-archive) and the [DashQ wire](https://github.com/taskqorg/dashq/blob/main/docs/contract/archive.md). It shares no content store, queue, schema, shipper or retention with telemetry.

## Approval and capture

`agentq archive enroll <https-origin> [--manual] [--headless]` requests `agent-history/1` through the existing device approval protocol, using the existing installation identity and protected connection under `data/connection`. The new approval preserves the connection’s other schemas; the archive has a separate schema and shipper, not a second enrollment for the same installation. `--manual` additionally requests the separately unticked `agent-history.manual` capability. Neither an observation grant nor a local capture flag grants archive authority. Without an active grant capture is off. `agentq disconnect` stops all sends locally before attempting revocation of the shared connection. Reconnecting to a different grant never sends the previous grant's backlog there. A normal snapshot enrollment preserves an already approved archive schema and manual capability; it never adds either on its own.

Runtime launches register private capture metadata asynchronously; their launch, input, polling, report and exit do not wait for archive storage or network. The service's separate archive thread discovers raw sources through `agent::history`, captures on its existing service cadence, including turn-end metadata notifications, and sends append-only ranges. A plain turn needs no service; absent shipper evidence reads unknown with a reason. A launched session carries `TASKQ_TASK` or `AGENTQ_LAUNCHER`; the same marker identifies managers launched by another product. Hooks register managers and explicitly enabled manual sessions without changing the native hook answer. Child sessions inherit capture authority from the registered parent, never from a matching project or model.

A manifest contains project, task, attempt, actor, entry, runtime, CLI version, model, effort, policy, account label, host, native session, parent session and instructions hash. Unknown conditions are null. Required identity labels use explicit unknown labels when unavailable. Conditions are append-only versions keyed by CoreQ's canonical JSON digest. Each attempt log begins its manifest at its observed first source byte; a resumed turn has its own source segment. Shared native transcripts have unknown caller conditions when no exact native turn boundary is available; their conditions are never guessed from the latest launch. Exact `agent.turn` event IDs bind to the known first byte of their attempt-log segment; missing bindings stay unknown and are never inferred from timestamps or model names.

Public capture registrations are caller-only, including native-looking formats and session labels. A private hook envelope can nominate an explicit transcript candidate. A launched NativeTurn can supply a private observed-source tuple only after its existing physical observation succeeds and accepts its own input. The tuple carries the actual path, original segment start, physical identity and observed raw prefix with runtime/session/project/home context; attachment, a baseline or recovery construction alone supplies no witness. The archive writer admits native scope after the existing native reader observes physical identity, prefix and native-session binding, and retains that checkpoint with the original context. The writer independently matches observed-source identity and raw prefix through the existing native reader before admitting its witness. The attached background path, segment start, session and terminal end update atomically with that separate private proof; per-turn bounds and attribution stay distinct from shared-native discovery. It revalidates that witness before new native reads or family discovery; absent, conflicting or unproven evidence never falls back to label-based discovery. Launch metadata alone supplies no native witness. The native capture keeps the existing run stop identity across recovery and is registered only after fresh accepted-input evidence; cached reports and recovery construction create no registration. Handoff copies already observed data and queues optional archive work; it adds no synchronous native read or wait. Public/caller, selected App, ACP, RPC and other bodies gain no native discovery authority from this handoff.

## Bytes and recovery

Native bytes are the source of truth; no normalized step, summary or inferred output replaces them. Scrubbing substitutes ASCII `*` for each byte of a recognized secret, preserving byte lengths, record framing and offsets. Thus archive ranges address the scrubbed stream and each chunk SHA-256 hashes the exact scrubbed bytes sent, never the unsent original. Replacement counts count recognized secret spans once per captured range. Raw prefix digests and native file identity remain private replacement detectors, never content claims. Media uses the whole scrubbed object's SHA-256 and total length; each range also carries its own digest. A reference to unavailable or changed media remains unavailable. Native media hashes identify the host bytes; media object IDs hash the scrubbed bytes sent. If scrubbing changes that hash, the original reference remains unavailable; neither hash is relabeled as the other.

Recorded app-server content comes only from the runtime's exact selected-source descriptor. Its `codex-app-server-selected/1` format denotes `native-jsonl-inbound-selection/1`: complete original inbound native lines selected after positive session/turn correlation, preserving their framing and arrival order before scrubbing. That format remains explicit in capture metadata, checkpoints, spool, wire and reader identities; interpretation may reuse the app-server decoder without relabeling the source as full stdout. Physical offsets address the selected file, never whole stdout. A changed format creates a distinct source generation. This is a caller-only observation source: no native Session, resolved provenance, discovery, generated-directory search, resume/reply authority or copied native capability claim follows. Foreign, global, unbound and diagnostic frames remain private; stderr/unfiltered stdout is never a fallback upload. Recovered/value-only/protected evidence cannot manufacture original selected bytes. Archive consumes the descriptor without parsing native fields and retains all existing grant, caller identity, snapshot, range/hash, media and scrub checks.

Native session media uses `Session::media`; owned caller logs use observation-only `History::caller` and `History::media`, including earlier physical revisions. Caller logs are inspected through private temporary copies of exactly their registered source segment; preceding or later log bytes grant no media authority. These read snapshots are removed after inspection. Unknown session inference uses only the same bounded physical snapshot supplied to the caller reader; an identity-free segment stays unknown. Caller labels never create native identity or authorize session-wide artifact discovery. Unknown native identity remains unknown; observed unbound or contradictory identity refuses the source. Assistant prose, arbitrary JSON subtrees and a selected session never authorize unrelated local files. Catalog paths obey project exclusions on capture and every pending send. URLs are never fetched. An inline object with a recognized decoded secret refuses its containing native source until a safe native representation is available; encoded original bytes cannot bypass scrubbing.

A session-scoped SQL view does not authorize raw database, WAL or index files that can contain other sessions. The producer refuses those raw sources with an explicit authority reason; derived rows are never described as original database bytes. Unsupported source representations remain unavailable rather than broadening capture.

Known shapes include provider and GitHub tokens, Bearer credentials, credential-valued JSON fields, and PEM private keys. Recognition runs over complete native records before ranges are split, so upload boundaries do not split recognition. Incomplete native tails wait for completion. Scrubbing is best effort, not a guarantee; archive content may still contain secrets. Manifest free-text conditions are scrubbed too. No telemetry record, diagnostic or status includes content, credentials or source paths.

Each project may set `.agentq-archive.json` with `{"exclude":["relative/path", "relative/directory/"]}`. Paths are relative to that project, literal, and exclude that path and its descendants; `.` excludes the whole project. No glob or implicit global rule is added. Symlink targets are checked against the same exclusions. Invalid or unreadable rules fail capture closed for that project and report unknown with a reason. A new rule stops future capture and delivery of the excluded sources; already accepted sink content requires explicit sink deletion.

Private state lives under `data/archive`, protected by the OS user boundary. Durable pending requests and source checkpoints are independent of telemetry. A source's contiguous `[start,end)` bytes, digest, manifest version and optional turn bindings are persisted before sending. Each queued range privately retains its original owner, capture class, project root and canonical root, grant identity, source scope, alias and canonical target, and reader evidence. Every send checks that original authority, current revocation and exclusions; a later registration cannot adopt or widen pending authority. Checkpoints without provable original authority retain their bytes and fail closed. Replacement generations preserve each pending range's original proof. Only an exact matching durable sink receipt advances its checkpoint; an uncertain response replays identical bytes. Media partial ranges accept a boolean `complete` state, including true when replaying an already verified whole object; the final range requires true. Missing or non-boolean completion never advances a checkpoint. Refusals and offline failures retain pending data. No archive retry limit, queue bound, timeout, cap, cache or free-space floor is added. The existing sink HTTP body limit determines wire chunking.

Replacement, truncation or rewriting creates a new source generation and records its predecessor; accepted bytes never change. Unsourced, incomplete, unreadable and excluded media remain explicit. Native, subagent, background, attempt-log and recorded app-server sources remain distinct. Unfiltered transport stdout/stderr is private diagnostic evidence, not authority for the selected native session; time boundaries cannot authorize foreign frames. Conflicting native identity refuses export until the runtime supplies an approved exact raw source. No URL is fetched for a native media reference. Host disable suspends archive capture and sending. The sink owns owner-only content access, audited reads, deletion and 365-day content retention; its index and metadata do not expire.

## Status and acceptance

`agentq archive status [--json]` shows grant and manual authority, shipper observation, last upload, pending bytes, oldest pending age, uploaded bytes, replacement count, scrub count, drops and class-only errors. No shipper, corrupt state or missing source is unknown with its reason, never healthy or zero loss. With no queue bound there are no policy drops; actual lost or unreadable sources are reported separately.

Qualification uses synthetic native sessions and a DashQ main sink built in a temporary private root, including durable readback, lost replies, offline resume, manifest changes, per-host manual refusal, exclusions, secret scrubbing, media and replaced/truncated sources. It never enrolls a real host, changes real client configuration, starts paid agent calls or touches pds18. Native Mac/Windows/Linux installation and production proxy/retention qualification remain separate from local contract checks.
