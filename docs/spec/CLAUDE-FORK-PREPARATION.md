## Blocking startup/effective-condition evidence

`SDKControlInitializeResponse` documents command/agent/model catalogues and account information, not an applied model/permission/retained-prefix receipt. `SDKSystemMessage` is metadata emitted at the start of each turn, normally after the prompt was submitted. Do not send a prompt to obtain that evidence, invent additional initialize fields, or treat a model catalogue / set_model receipt / persisted setting as applied state. `get_context_usage` defaults to full token-count API calls; summary explicitly avoids those calls, but its model-only response still does not prove child permission mode, retained chain or absence of autonomous work. `background_tasks` is a mutator (Ctrl+B), not an inventory query. It must not be sent as read-only evidence.

Until a source-established pre-prompt child identity + effective-condition + retained-prefix readback and safe autonomous-work boundary exist, even an exact revalidated tip returns `claude-fork-startup-evidence-unsupported` before child admission, spawn or input. No fake successful double or advertised capability may turn that partial behavior into completed support. Source/report/snapshot/files and private lineage stay unchanged on this pre-write refusal; no mutation intent is created for an operation never submitted.

The next actual native path must admit a fresh child and persist its private selected-boundary lineage before native creation; use one owned child transport for native fork and one explicit prompt after verified child identity/conditions/prefix and unchanged-parent readback. Unknown mutation must retain the existing durable owner fence without replay. No pending C285 capability, request generation or parent reply token may transfer. No copied-prefix billing, archive delivery or file restoration is inferred.

## Smallest history-owner seam still needed

Existing `Session.steps`, `Session.read_bytes`, `Step.source` and `Step.origins` can revalidate a physical record, but expose no uniform terminal native chain cursor or completed-whole-turn association. Broader support needs the history owner to associate the existing exact Step and source checkpoint/generation with its adapter-native prompt/turn and last retained chain entry, including tool-result carriers and transcript-only attachments, or return unknown/refusal. Keep native versus snapshot ranges, opaque source labels and original versus scrubbed bytes separate. The resolver remains read-only and grants no mutation/reply authority; the native adapter must recheck its witness under the current owner. No new shared signature/type/schema is proposed here, and existing Source.parent_step retains its native call-ID meaning.
