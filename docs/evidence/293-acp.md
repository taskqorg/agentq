# ACP candidate qualification

The shared adapter is tested through the runtime trait with a portable JSONL server double. It covers start, offered-choice validation, duplicate/late response refusal, model and mode controls, typed tools, unknown updates, resume replay suppression, native cancellation, known-bad server rejection and EOF without completion. Low-level stream/agentapi seams remain solely for comparison proof.

## Native macOS observation

Installed `agy 1.5.2`, macOS arm64. The test copied the existing login into a temporary Gemini home; the source profile was read only. No deployment or service action was performed.

An empty workspace stayed empty after `session/new` and a small real text turn. Built-in skills appeared only under the temporary home, with no `skills/system/run-workflow/SKILL.md` in the workspace. A fresh unsigned home returned `Authentication required`, rather than picking up the working profile's login.

`cargo run --locked -p agentq-runtime --example qualify_acp` then compared ACP and stream with the same file-read task and a remembered-content resume. Both executed a native tool, returned `ACP_NATIVE_PROOF` and preserved the workspace's sole fixture file. ACP load replay emitted no old live tool events. ACP cancellation returned the native `cancelled` stop reason; killing the stream process produced no native cancellation receipt.

| Transport | First input / output | Resume input / output | Cancellation |

| ACP | 9514 / 119 | 2294 / 22 | Native `cancelled`; unreported tokens unknown |
| Stream | 9463 / 120 | 2295 / 22 | Process stopped; native cancellation unknown |

These are observations of small turns, not a performance comparison or full runtime qualification. ACP model/mode controls and approval choices have deterministic protocol proof; their complete native qualification remains open. Canonical typed steps use merged #305. A read-only projection of the retained real ACP log through `agentq agent history` returned the tool as completed with its contributing origins and retained the answer marker. Canonical #284 worker preflight is now used before ACP input, including client version, account, capacity, workspace, policy, inputs, storage and cleaned account environment. ACP sign-in and canonical controls still depend on #286/#285.

## Platform boundary

Windows `agy 1.5.2` and the portable ACP check passed in a private temporary clone. The follow-up cleanup proof below also passed on the installed native server without login or a model prompt. No reusable login file was available in the checked Windows profile paths, so paid native Windows turns remain unqualified. The stream implementation is retained until the macOS and Windows comparison, history and login gaps are resolved. Stream and agentapi low-level seams serve comparison proof only; high-level launch/resume always use ACP, with no automatic compatibility path. Consumers must use an ACP executable and a Gemini root home. No platform is called fully qualified by the adapter tests or CI alone.

The stateful ACP run explicitly refuses process checkpoints; the portable protocol check proves that refusal. Existing process-identity recovery checks continue to cover stateless CLI runs. No ACP recovery or resubmission is inferred from a saved native session ID.

The 9 MiB protocol regression reproduced the inherited Codex record cap before correction, then verifies large native replies and input without a new limit; ACP has unbounded queues. Terminal poll/progress closes stdin and only tries process exit; an unexited server reads null `session-process-running`, with final cleanup owned by the run. Native transcript records serialize once before writing, avoiding per-character file writes.

## Independent review corrections

The independent pending-permission probe first returned `Unknown` after its 5-second caller deadline and recorded no response to the permission request. With the same cancellation scenario (plus a version fixture and existing temporary account directory required by canonical preflight), it returned native `cancelled` in about 26 ms and retained the cancelled permission response. The portable check also covers a request racing cancellation, no caller deadline, and a server parked indefinitely after its terminal reply: poll/progress still returns with a named unknown process exit.

Every public Antigravity home is now a Gemini root, including named accounts, quota, identity and protected paths. Isolated fixtures prove credential lookup under `antigravity-cli`, root-local `oauth_creds.json`, expired quota readback, read-only identity and protection of `<root>/config`. Consumers must stop passing an Antigravity data directory or relying on the retired agentapi executable override.

The canonical preflight version result refuses known bad/below-minimum clients before ACP spawn; initialize omission of agentInfo cannot bypass it. Checked wire payloads cover every field consumed by initialization, session selection, permissions, updates, completion and usage. Legal null-ID errors remain in raw history and appear as protocol-error metadata. Native Windows 1.5.2 returns both `loadSession` and `load_session`; both fields are checked separately. Unknown extensions remain raw, and malformed consumed fields are retained before refusal.

Windows proof used a private temporary clone and temporary HOME/USERPROFILE/APPDATA/LOCALAPPDATA/GEMINI_HOME. The portable cmd shim test proves caller setup survives and an inherited child cannot survive native job teardown. `cargo run --locked -p agentq-runtime --example qualify_acp_cleanup` then ran the installed `agy 1.5.2` through a private cmd shim: 2 original processes observed, both gone after refusal cleanup, no workspace writes, no model prompt submitted, native result `Authentication required`. The source login/profile and service were not changed. This qualifies owned native process cleanup; it does not qualify the still-open paid Windows task/resume/token/history comparison or ACP sign-in.
